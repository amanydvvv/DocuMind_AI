## 1. Project Overview

DocuMind AI is a production RAG (Retrieval-Augmented Generation) assistant for querying technical documentation over natural language.

- **Backend**: FastAPI + SQLAlchemy 2.0 (async) + PostgreSQL 17 + pgvector (Supabase, `ap-southeast-1`)
- **LLM stack**: Groq `llama-3.1-8b-instant` (generation), `openai/gpt-oss-20b` (eval judge), Gemini `gemini-embedding-001` (768d embeddings), Gemini vision OCR fallback (`qwen/qwen3.6-27b` on Groq)
- **Frontend**: React 19 + Vite + vanilla CSS tokens (dark theme)
- **Deployed**: Frontend on Vercel (`docu-mind-ai-iota.vercel.app`), backend on Render (`documind-ai-97t5.onrender.com`), DB on Supabase
- **Repo**: `https://github.com/amanydvvv/DocuMind_AI`, branch `main`

### The core WIP change — new prompt template
`RAG_PROMPT_TEMPLATE` in `backend/app/services/generation.py` was rewritten:

- **Old style**: "System Instructions & Rules" (1–6), "Hard Negative Constraint", "Content Over Filename Priority", "Document Counts", "Raw relevance" shown in context, `User Query:` label, memory injected by string-prefixing the template.
- **New style**: compact `GUIDELINES:` block, `Prior Context:`/`Context:`/`User Question:` labels, `<thought_process>`/`<answer>` scaffold, **hard-coded decline phrase**: `"I do not have sufficient information in the loaded documents to answer this question."`
- `conversation_summary` is now a proper `PromptTemplate` variable (both `generate_answer` and `generate_answer_stream`), no more string-concat memory injection.
- `_format_context_text` now emits `[{display_title}]\n{content}` — **removed page numbers and `Raw relevance:` lines from the context (anti-leak)**.

### WIP test status (verified 2026-08-10)
`python -m pytest tests/test_guardrails.py tests/test_cot_buffer.py -q` → **88 passed, 0 failures**.

> Note: run from `backend/` dir. Python 3.10.6 in use; google-api-core emits a FutureWarning (harmless).

### Why the decline phrase matters
The exact string `"I do not have sufficient information in the loaded documents to answer this question."` is:
1. The instruction-followed decline the model must emit when context can't answer;
2. NOT in `PROMPT_LEAK_FRAGMENTS` (so it passes `validate_output`);
3. In `test_rag_quality.py::test_out_of_scope_fallback_exact_match` and in `test_integration.py`'s phrase allowlist.

Keep this phrase in sync everywhere. If the template changes, `test_guardrails.py::test_validate_output_leak_fragments_track_live_template` (whitelist `template_fragments`) and `test_rag_quality.py::test_all_fragments_have_test_coverage` (exact-set equality) will fail loudly on drift — do not delete those tests.

## 7. Gotchas & Conventions

1. **Do not add comments to code** unless asked; mimic existing style.
2. **Line endings**: git warns "LF will be replaced by CRLF" on Windows — harmless, don't churn line endings.
3. **Prompt-leak list sync**: any change to `RAG_PROMPT_TEMPLATE` must keep `PROMPT_LEAK_FRAGMENTS` (guardrails.py) + both drift tests aligned, or tests fail.
4. **Decline phrase** is a single canonical string — search `sufficient information in the loaded documents` before changing wording.
5. **`raw_bytes` migration** (`3d4e5f6a7b8c`) must be deployed before relying on PDF file endpoints; `scripts/rescue_pdf_bytes.py` backfills legacy rows.
6. **Concurrency**: `update_conversation_summary` runs as Starlette `BackgroundTask` on streaming — keep that.
7. **Rate limiter**: `CF-Connecting-IP` only trusted when peer host is private — don't regress.
8. **Baseline runs cost money** (76 LLM calls); use `run_eval.py run --subset` or sample mode for quick checks.
9. Frontend/UI work follows the token-based dark theme system (`index.css` tokens) from Phase 1–2.
10. `.env` is gitignored; keys live in `backend/.env` (GROQ/GEMINI/DATABASE_URL).
11. **Jules admin router** (`/api/admin/jules/*`) is **internal tooling only** — it lets the deployed
    backend programmatically trigger Jules autonomous coding sessions and poll their status. It is
    NOT user-facing and must never be exposed to end users (real attack surface + API cost risk).
    Controlled by `JULES_ENABLED` env var (default `true` — key is live in production).
    To disable: set `JULES_ENABLED=false` in Render env vars. No code change needed.
